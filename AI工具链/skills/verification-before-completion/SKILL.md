# 完成前验证（UE5 版）

> 源包（Roblox）版本的前提是"无单测框架、无 CI"，所以只能靠 Play F5 肉眼观察。
> **UE 有 Automation Test——这条必须升级**；但 UE 的编译与启动是分钟级，且 `-nullrhi` 下渲染断言无效。所以：**能自动验的必须自动验，不能自动的必须留可回溯证据，且不得混为一谈。**

## 铁律

```
没有新鲜的验证证据，不许宣称完成。
```

"新鲜"= 在本轮改动**之后**取得的证据。上一轮的通过记录一律过期。

---

## 门控函数

在宣称任何状态或表达满意之前：

1. **确定**：什么证据能证明这个结论？（编译？Automation？PIE？截图？diff？）
2. **获取**：实际执行——跑 UBT、跑 Automation、PIE 观察、截图
3. **阅读**：完整读输出（含 warning、含 `LogAutomationController` 的失败行），不要只看最后一行
4. **判断**：证据是否支持结论？
   - 否 → **用证据说明实际状态**（"`Project.Economy.PriceRule` 失败，期望 100 实得 0"）
   - 是 → **带证据陈述**（"AC-2 通过：`Project.Economy.Buy_Insufficient` 绿，两值未变"）
5. **只有此时**才能下结论

跳过任一步 = 说谎，不是验证。

## 声明 → 证据（摘要；权威表在 `开发规范/验证与门禁.md` §2）

| 结论 | 需要的证据 | 不够格 |
|---|---|---|
| 编译通过 | UBT 输出 `0 error`（含模块依赖解析成功） | "代码看着没问题" |
| 逻辑正确 | 对应 Automation Test `Success` | "逻辑上应该对" |
| 数值正确 | 表驱动用例（边界/负值/溢出/NaN）全绿 | 手动点了几下 |
| 存档不丢 | 写入→读取→迁移 三段用例绿 + `SchemaVersion` 检查 | "保存过一次" |
| `UPROPERTY` 改名安全 | 老存档实测载入 + 字段值正确（截图/日志） | "加了 Core Redirect" |
| Bug 已修 | 先复现（红）→ 修 → 同一用例转绿 | "改了这行应该好了" |
| RPC 无作弊面 | 非法输入用例全绿 + 非权威端被拒 | "加了 `HasAuthority()`" |
| 复制正常 | 双端验证（L2 或 L3 + 双端日志） | "单机测过" |
| UI 正确 | 改前/改后截图（**必须在真实渲染下**） | "`-nullrhi` 没报错" |
| 性能达标 | `stat unit` / Unreal Insights 截图 + 帧时间数字 | "感觉挺流畅" |
| BP 装配正确 | 截图 BP 图 + 说明职责（**人工**） | "蓝图连上了" |
| 模块边界没破 | `*.Build.cs` 白名单校验通过 | "我没加依赖" |
| Phase 完成 | 逐条核对产物 + 验收标准 | 单个用例过了 |
| 可以归档 | L1 全绿 + 门禁 G1–G9 全部通过 | "审核说没问题" |

## 常见借口 vs 现实

| 借口 | 现实 |
|---|---|
| "逻辑上应该能行" | 去写/跑那条 Automation Test |
| "我有信心" | 信心 ≠ 证据 |
| "就这一次不测" | 没有例外 |
| "编译过了就行" | 编译只证明类型与反射宏对 |
| "`-nullrhi` 跑过了" | 那只证明逻辑，渲染/UMG 完全没验 |
| "上次测过是好的" | 代码又改了 = 证据过期 |
| "reviewer 说通过了" | 自己看 diff，独立核对 |
| "蓝图很简单，不用看" | BP 不可 diff，人工 M2 必须留截图 |
| "Live Coding 生效了" | Live Coding 不保证全部改动生效（结构/反射变更需重启） |
| "换个说法这条规则就不适用" | 精神大于字面 |

## 证据写法（正/反例）

**Automation Test**
```
✅ `Project.Economy.*` 全绿（18 tests, 0 failures），新增 5 条覆盖 AC-1..AC-4
❌ "测试应该没问题"
```

**Bug 修复**
```
✅ 先跑 `Project.Economy.Buy_Concurrent` 复现失败（2 次发货）→ 加 requestId 幂等 → 重跑绿
❌ "加了幂等判断，应该好了"
```

**存档 / UPROPERTY 改名**
```
✅ 用 v1 存档（含旧字段名）载入 → Core Redirect 生效 → 日志确认新字段值 = 老值（附日志行）
❌ "加了 Core Redirect，应该能读"
```

**RPC 权威**
```
✅ 非权威端调 `TryBuy` → 返回 false 且状态不变（用例 `Economy.AuthorityOnly` 绿）
❌ "首行加了 HasAuthority"
```

**表现层**
```
✅ 截图：1280×720 与 2560×1440 下按钮均居中未溢出（附两张图）
❌ "用了 Anchor，应该自适应"
```

**Phase 收尾**
```
✅ 重读 03-plan.md 的 12 项任务 → 逐项核对 → 11 完成 1 延期（记 05-issues.md）
❌ "主要功能都做完了"
```

## 何时必须使用

- 任何"改好了 / 验证通过 / Phase 完成 / 可以归档"的声明
- 任何满意表达（"搞定""完美""这下没问题了"）
- `/workflow archive`、git commit、进入下一 Phase 之前
- 采信子代理结论之前（独立看 diff，不看它的措辞）

---

## 为什么这很重要

- 未验证的东西会被**归档进 `spec/` 成为"当前真相"**，后续所有迭代建立在假前提上
- AI 生成代码的最大风险不是"写得差"，而是**"看起来对"**——只有证据能区分
- UE 特有陷阱：`.uasset` 改动在 diff 里只显示 `Bin → Bin`，**看起来像没改**，实际可能改了装配
- 诚实底线：失败就说失败并附输出；跳过就说跳过；完成且验证了才平铺直叙说完成

---

## 底线

**验证没有捷径。** 跑 UBT、跑 Automation、PIE 里看一眼、截图、看 diff，然后才能宣称结果。没有商量余地。
