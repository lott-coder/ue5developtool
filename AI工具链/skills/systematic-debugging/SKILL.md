# 系统化调试

> 核心纪律：**先证伪假设，再改代码**。改代码"试试看"不是调试，是抽奖。

## 四阶段

```
1 稳定复现 → 2 定位根因 → 3 最小修复 → 4 回归验证
   ↑__________________________________________|
        （任何一步失败，回到 1，不要跳到 3）
```

---

## 阶段 1：稳定复现

**目标**：得到一个**必然变红**的测试或用例。

| 动作 | 产出 |
|---|---|
| 描述症状（什么操作 → 什么异常现象） | 一句话问题陈述 |
| 找最小复现路径 | 最少步骤/最少数据 |
| 写成测试（优先）或记录手动步骤 | 红着的测试 / 可重复步骤表 |
| 确认反复执行结果一致 | 复现率 100% |

**不能复现就不要修**。不能复现意味着：你无法验证修复，也无法防止回归。

若确实无法稳定复现（时序/并发/平台相关）：
- 加日志/断言把它变成可观测（记录状态快照）
- 用压力循环放大（跑 N 次）
- 记录为"疑似"，**不得声称已修复**

---

## 阶段 2：定位根因

**方法优先级**（从便宜到贵）：

| # | 方法 | 适用 |
|---|---|---|
| 1 | 读代码 + 读 `knowledge/{module}.md` 的「踩过的坑」 | 先查是不是已知问题 |
| 2 | 加日志/断言，打印状态快照 | 状态在何时变错 |
| 3 | 二分：注释/回滚一半改动 | 大面积改动后出问题 |
| 4 | 断点单步 / Profiler | 时序、性能、生命周期 |
| 5 | `git bisect` | 不知道哪次提交引入 |

**必须回答的问题**：
- 错在**哪一步**？（输入 → 处理 → 存储 → 读取 → 展示）
- 错的是**数据**还是**时序**？
- 是否只在特定**顺序/并发/边界**下发生？
- 能否**解释全部症状**？（只能解释一部分 = 还没找到根因）

**根因判据**：能解释所有观察到的现象，且**去掉它现象就消失**。

---

## 阶段 3：最小修复

| 纪律 | 说明 |
|---|---|
| 改最小面 | 只改根因所在处，不顺手重构 |
| 一处根因一处修复 | 不要"顺便也把这改了" |
| 不引入新抽象 | 修复阶段禁止重构 |
| 保留失败证据 | 先让测试红着，修完再跑绿 |

**允许的"修复"包括**：改代码、改配置、改调用顺序、加校验。
**不允许**：改测试预期来迁就实现、关掉断言、加 `try/catch` 吞掉。

---

## 阶段 4：回归验证

1. 原复现用例 → **绿**
2. 相邻模块测试 → **仍绿**（防连带破坏）
3. 补一条**防回归测试**（如果没有现成的）
4. 在 `05-issues.md` 记录：现象 / 根因 / 修复 / 防回归用例

> 没有第 3 步，同类问题一定复发——**修复的价值一半在防止复发**。

## UE 常见根因清单

| 现象 | 常见根因 |
|---|---|
| 空指针只在某个地图出现 | 初始化顺序 / `BeginPlay` 时其他 Actor 未就绪 / `GameMode` 在客户端不存在 |
| 改了代码行为没变 | Live Coding 未覆盖结构变更（需重启）/ 资产里有序列化旧值覆盖默认值 |
| 蓝图改了不生效 | 继承的 C++ 类未重编译 / 父类属性在 BP 里被 override |
| 联机不同步 | RPC 前缀写错（`Server`/`Client`/`Multicast`）/ 属性未加 `Replicated` / 未在 `GetLifetimeReplicatedProps` 注册 |
| 只有主机看得到效果 | 逻辑写在 `HasAuthority()` 分支内但需要广播（缺 Multicast） |
| 存档字段读不出来 | `UPROPERTY` 改名未配 Core Redirect / 未标 `SaveGame` |
| 内存持续增长 | `UPROPERTY` 指针未清 / 委托未解绑 / 计时器未清 |
| 崩溃在 GC | `UObject*` 成员缺 `UPROPERTY`（被 GC 回收） |
| Tick 掉帧 | Tick 里 `FindComponentByClass` / `GetAllActorsOfClass` / 同步加载 |
| 编辑器正常、打包异常 | 只在 Editor 模块的代码被运行时引用 / 资产未被打包（未在 cook 引用链里） |
| 资源加载失败但路径看着对 | 重定向器未清理 / 写死 `/Game/` 路径 / 资产被移动 |

## 反模式

| 反模式 | 后果 |
|---|---|
| 不复现就改代码 | 无法验证，可能引入新 Bug |
| 一次改多处 | 无法归因，破坏面扩大 |
| 用 `try/catch` 吞异常 | 掩盖根因，故障后移 |
| 改测试迁就实现 | 门禁失效 |
| 找到"看起来像"的原因就停 | 症状复发 |
| 修完不补回归测试 | 同类问题必然复发 |

---

## 一句话

**调试是"证明"，不是"尝试"。** 你能稳定复现、能解释全部症状、能证明修复有效——三者缺一，就还没调完。
