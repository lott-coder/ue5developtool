# 工作流执行（Phase 0–5 · 阶段门禁）

> 本文是 `/workflow plan` 的执行细则。**核心机制与引擎无关**：换引擎不改流程，只改各阶段的"检查项来源"。
> 检查项来源：架构 → [架构.md](架构.md)；编码 → [编码约定.md](编码约定.md)；工程 → [工程与资源.md](工程与资源.md)；证据 → [验证与门禁.md](验证与门禁.md)。

版本：v1.0.0（UE5 移植版）｜更新：2026-11-12

---

## 快速开始

```
/workflow init minor economy purchase        # 初始化迭代（模块 / 子分类）
/workflow plan --prd docs/prd.png            # 带 PRD（Phase 0）
/workflow plan                               # 默认 brainstorm 交互模式
/workflow plan --direct                      # 快速模式
/workflow plan --unattended                  # 无人值守（见无人值守安全.md）
/workflow verify <phase>                     # 手动触发审核
/workflow status                             # 查询状态
/workflow archive purchase                    # 归档（delta 合并进 spec/）
```

---

## 执行红线（严格禁止）

- ❌ **禁止跳过审核**：每阶段完成后必须调 `plan-reviewer` / `code-reviewer`
- ❌ **禁止审核后直接进下一阶段**：必须 `AskUserQuestion` 展示并等确认
- ❌ **禁止批量询问**：一次只过一个阶段
- ❌ **禁止先做后补文档**：规划必须先落 `change/{module}/_tmp/`
- ❌ **禁止忽略阻断项**
- ❌ **禁止跳过归档**
- ❌ **禁止行为变更无 delta 归档**
- ❌ **禁止 delta 校验不过就归档**
- ❌ **禁止手改 `spec/{module}.md`**
- ❌ **禁止跳过验证证据**（见 [验证与门禁.md](验证与门禁.md) §2）
- ❌ **禁止业务逻辑进 Blueprint**（见 [架构.md](架构.md) §7）——这是 UE 版新增红线
- ❌ **禁止自行假设**

### `--unattended` 例外

自治模式下"审核后询问用户"被**严重度矩阵自动决策**替代，但**审核本身不跳过**。详见 [无人值守安全.md](无人值守安全.md)。

## Phase 0：需求文档解析（可选）

**触发**：`--prd <路径>`，或对话中直接给了 PRD/截图/PDF。

1. 调 `prd-reader` → `change/{module}/_tmp/00-prd-analysis.md`
2. 该文档必须标注：功能需求（FR-xx）、**每条的层归属**（`GameCore` / `GameFramework` / `GameServices` / `GameUI`+`GamePlay`）、是否涉及 Blueprint 装配、依赖的 DataAsset/DataTable
3. 主会话读它作为 Phase 1 输入
4. 自动进 Phase 1

---

## Phase 1：需求分析

**默认（brainstorm-design）**：
1. 探索上下文：相关模块与类型、`knowledge/{module}.md`、`change/{module}/` 历史
2. **在途契约软检查**：读 `change/versions.json` 找出其它 `status=wip` 模块，汇总其在途的接口/复制属性/存档/资产契约（不阻断）
3. 逐轮澄清（**一次一问**，优先选择题）：核心目标 / 玩法机制 / 目标用户 / 成功标准 / 约束 / 引擎维度
4. 提出 2–3 个方向方案（精简 / 标准 / 旗舰）
5. 分块展示 → 每块 `AskUserQuestion` 确认
6. 写 `01-requirements.md` → 最终审查
7. `plan-reviewer` 审核 → 写 `04-review-report.md`
7.5 （可选，建议必做）调 `experience-designer` 从留存/变现视角评审 → 意见追加到同一报告；它**不阻断流程**，但"这需求不值得做"的结论必须原样上报
8. 展示 + 按答复整理 → 用户确认 → Phase 2

**`--direct`**：直接写 `01-requirements.md`，审核流程一致。

**本阶段检查项（UE 特化）**：
- 每条需求是否标注层归属（`GameCore`/`GameFramework`/`GameServices`/`GameUI`/`GamePlay`）？
- 权威模式（Standalone / Dedicated）是否明确？若需求暗示联机，是否说明不支持 Listen Server？
- 是否需要新增/修改 `UDataAsset` 或 `UDataTable`？
- **是否需要在 Blueprint 侧装配？**（若要，明确"BP 只做装配"的边界）
- 是否需要改 `UPROPERTY` 名或存档 `SchemaVersion`？（改名 = 丢数据，要在需求阶段就知道）
- 验收标准是否按 [验证与门禁.md](验证与门禁.md) §5 表格写（含证据级别）？

**产出**：`01-requirements.md`

## Phase 2：系统设计

**默认（brainstorm-develop）**：
1. 深入代码：定位相关模块/类型、现有接口、`knowledge/{module}.md`
2. 逐轮澄清技术维度（一次一问）：架构落位 / 数据结构 / 交互流程 / 复制与网络 / 兼容性 / 复杂度
3. 提出 2–3 个技术方案（含层落位、数据流、类型清单、复制策略、性能、验证）
4. 分块展示（架构 → 数据结构 → 交互 → 性能与验证）→ 每块确认
5. 写 `02-design.md`（**核心重点前置** + 后补伪代码）
6. **产出 `07-spec-delta.md`**（涉及行为变更时）：
   - ADDED / MODIFIED / REMOVED 三段
   - MODIFIED/REMOVED 引用现存 `R{n}`；ADDED 用新 `R{n}`
   - 每条至少一个「**当…则…**」场景，"则"落在**权威端**
   - **在途契约终检**：比对 C1–C5（见下），0 冲突则在 `02-design.md` 头部记一行
6.5 （可选）调 `ue5-systems-engineer` 评估模块落位、复制策略、可测性与 Blueprint 边界 → 结论并入 `02-design.md` 的「架构约束遵守声明」
7. `plan-reviewer` 审核 → 追加 `04-review-report.md` → 展示 → 确认
8. 用户确认 → Phase 3

### 「权威端」在 UE 里的定义（C7 依据）

| 模式 | 权威端 | 场景「则」的写法 |
|---|---|---|
| **Standalone** | 进程内（`HasAuthority()` 恒 true） | "则 Gameplay 层唯一写入口执行…" |
| **Dedicated** | 服务器（`HasAuthority()` 为 true 的一侧） | "则服务器执行…，客户端仅收到复制结果" |

**禁止**写成"则客户端自行显示/决定…"——那是表现层裁定。

### 共享契约冲突表（C1–C5）

| # | 共享契约 | 冲突形态 | UE 载体 |
|---|---|---|---|
| C1 | 公开接口 / 委托 / RPC 名 | 同名冲突、前缀错导致静默不复制 | `UFUNCTION` 名、`DECLARE_*_DELEGATE` 签名 |
| C2 | 存档分区字段 / `SchemaVersion` | 两系统写同一分区互相冲掉；改字段无迁移 | `USaveGame` 子类字段 |
| C3 | 配置资产结构 | 同 DataAsset 加字段导致对方读取崩 | `UDataAsset` / `UDataTable` 列 |
| C4 | 资产引用 / 重定向 | 重命名后未 Fix Up Redirectors、写死 `/Game/` 路径 | `TObjectPtr` / `TSoftObjectPtr` / 字符串路径 |
| C5 | 共享子系统接口 | 改签名导致调用方断 | `UGameInstanceSubsystem` / `UWorldSubsystem` 公开方法 |

**比对范围**：本模块 `02-design.md` 的接口清单 + 复制属性 + 资产依赖，逐项比对其它 wip 模块同类章节及其 `07-spec-delta.md`。

**产出**：`02-design.md`、`07-spec-delta.md`

## Phase 3：计划制定

1. 确认接口约束（`UFUNCTION` 签名、委托名、复制属性、`SchemaVersion`）
2. 写 `03-plan.md`：任务清单、依赖、回滚
3. **每项任务必须标注**：
   - 输出文件路径（`Source/GameFramework/Private/Economy/EconomySubsystem.cpp`）
   - 模块归属（`GameCore`/`GameFramework`/…）
   - 需要的测试（L1/L2）
   - **是否涉及资产修改**（DataAsset / DataTable / BP / Level / Core Redirect）——单列一节
4. `plan-reviewer` 审核（最多 3 轮修复）
5. 追加 `04-review-report.md`
6. 生成执行摘要
7. `AskUserQuestion` 展示 → 确认 → Phase 4

**产出**：`03-plan.md`

---

## Phase 4：代码执行

1. 按 `03-plan.md` 逐项执行，逐项更新状态
2. 遇阻记录到 `05-issues.md`
3. **先写测试再写实现**（至少对 `GameCore` / `GameFramework` 的行为）
4. 完成后调 `code-reviewer` 审查
5. `AskUserQuestion` 展示 → 确认 → 按答复整理报告
6. 修复 → 重跑门禁（[验证与门禁.md](验证与门禁.md) §3）
7. 通过 → Phase 5

**本阶段硬要求**：
- 每个新增行为至少 1 条 L1 Automation Test
- 改 `GameCore`/`GameFramework` → 跑 Automation 全量（`Project.*` 过滤）
- 改 UMG/表现 → 留 L4 截图
- **改 `UPROPERTY` 名/类型 → 必须配 Core Redirects 或废弃过渡，并验证老存档可读**
- **新增/修改 BP → 说明改了什么装配，且确认未引入业务规则**
- 涉及复制 → 必须双端验证（L2 或 L3 + 日志）

---

## Phase 5：知识沉淀与归档

1. 分析影响面，确定涉及的 `knowledge/{module}.md`
2. `/knowledge-set <module>`（默认 dry-run）
3. 写 `06-knowledge-update.md`
4. 更新 `knowledge/README.md` 索引
5. 确认 `07-spec-delta.md` 已产出 → 跑工具校验：
   `python AI工具链/tools/spec_tool.py validate --module {module}`
6. 归档（**工具执行，禁止手工合并**）：
   `python AI工具链/tools/spec_tool.py archive --module {module} --version {v} --subcategory {sub} --apply`
   → delta 合并进 `spec/{module}.md`；工具内部顺序为「校验 → 合并 spec → 移动文档 → 更新索引」，失败自动回滚
7. 回写工作计划（如有 `docs/WorkPlan_*.md`）

## 审核结果处理

| 结果 | 处理 |
|---|---|
| 通过 | 展示 → 用户确认 → 下一阶段 |
| 有条件通过 | 展示 → 用户决定是否修复 → 修复后重审或确认 |
| 不通过 | 展示 → 必须修复 → 重审 → 再确认（最多 3 轮） |

```
产物完成 → 调 reviewer → 写 04-review-report.md
    ↓
AskUserQuestion 展示摘要
    ↓
├─ 确认通过 → 追加确认记录 → 下一阶段
├─ 修复后重审 → 修复 → 重审 → 再问
└─ 讨论详情 → 澄清 → 更新报告 → 再问
```

## UE 特有的"不能自动化"环节（显式登记）

以下检查**只能人工**，必须在 `05-issues.md` 留记录，不得假装已自动验证：

| # | 检查 | 为何不可自动 | 人工记录要求 |
|---|---|---|---|
| M1 | `UPROPERTY` 改名未丢数据 | 需老存档实测 | 截图/日志：老存档载入后字段值 |
| M2 | Blueprint 装配正确 | 图不可断言 | 截图 BP 图 + 说明职责 |
| M3 | 重定向器已清理 | 工具能查数量，不能判断"该不该存在" | 列出清理的资产 |
| M4 | UMG 多分辨率/多语言 | 需真实渲染 | 截图（≥2 种分辨率） |
| M5 | 手感/镜头/打击感 | 主观 | 录屏 + 一句描述 |
