# 多会话与独占资源

> 迁移自源包 `mcp-lock`（多会话抢 Studio Play 的仲裁锁）的**引擎无关内核**。
> 场景换成 Unity Editor / UE Editor，问题完全一样：**多个 AI 会话或多人同时驱动同一个独占资源，会互相打断，且证据失真。**

---

## 1. 什么算"独占资源"

| 资源 | 为什么独占 | 冲突后果 |
|---|---|---|
| 编辑器实例（Unity / UE） | 一个工程只能被一个编辑器进程稳定打开 | 后开者拿到只读/副本，改动不落盘 |
| **运行/播放**（Play / PIE） | 同时只有一个前台的运行时 | 后启动者打断前者，截图与日志互相污染 |
| 构建目录（`Library/`、`Intermediate/`） | 构建产物不并发安全 | 构建失败或产出损坏 |
| 资产写入（`.unity`/`.prefab`、`.uasset`/`.umap`） | 二进制/语义合并不可行 | 覆盖丢失、重定向器堆积 |
| **同一个 `change/{module}/_tmp/`** | 一组迭代文档只对应一次迭代 | 两个会话改同一批文档，互相覆盖 |

---

## 2. 锁协议（FIFO + 租约）

```
acquire(任务名, 等待超时)
  ├─ 无人持有 → 立即获得，返回 token
  ├─ 有人持有 → 排队（FIFO），轮询等待
  └─ 超时 → 自动撤销自己的排队项，返回失败（不静默降级为"我也跑"）
使用中 → 每 N 秒 heartbeat 续租
release(token)
  └─ 只释放自己；**绝不代晋升队首**（防幽灵持有者）
```

**四条硬规则**：

| # | 规则 | 理由 |
|---|---|---|
| 1 | **释放不代晋升** | 由仍在轮询的队首下一拍自取。代晋升会在持有者实际已死时制造"幽灵持有者" |
| 2 | **租约到期才算死** | 默认 10 分钟；心跳间隔 ≤ 租约/3 |
| 3 | **排队者 10 秒无心跳即清扫** | 区分"在等"与"已经崩了" |
| 4 | **acquire 超时前先自撤** | 否则队列里留下死项，后续全部卡住 |

## 3. 最小落位（不引入服务）

不必像源包那样跑 HTTP 守护进程。用**文件锁 + 约定**即可覆盖单机多会话：

```
change/.editor.lock          # 或 .mcp/lock.json（仅观察，不作权威）
{ "task": "PIE 验证", "pid": 12345, "token": "…", "acquiredAt": "…", "heartbeatAt": "…" }
```

| 操作 | 做法 |
|---|---|
| acquire | 文件不存在 → 原子创建（`O_EXCL`）；存在且心跳 < 10 分钟 → 排队等待 |
| heartbeat | 每 60 秒更新 `heartbeatAt` |
| release | 只删自己 token 的那份 |
| stale 清扫 | 存在但心跳 > 10 分钟 → 记录警告后接管 |

**`.mcp/` 或锁文件必须进 `.gitignore`**（锁状态不入库）。

## 4. 与流程的三处衔接

| 场景 | 规则 |
|---|---|
| 无人值守执行 | `change/.unattended.lock`（防重复规划）——见 `无人值守安全.md §13` |
| 归档合并 | `change/.archive.lock`（防重复合并）——由 `tools/spec_tool.py` 实现 |
| **编辑器/播放** | 本文件定义的锁；**进 Play/PIE 前必须持有** |

三把锁互不替代：不持有规划锁也能进 Play，但**不持有编辑器锁就不该进 Play**。

---

## 5. 无锁时的降级规则

没有条件实现锁时，至少遵守：

| 情况 | 做法 |
|---|---|
| 发现编辑器已在运行且**不是自己启动的** | **先问用户**，不自动关闭/接管 |
| 发现上一次运行残留（有 `lastPlay` 记录） | 可判定为前任务残留，允许接管并记录 |
| 用户正在手动测试 | **不抢**；把验证步骤写给用户，等其完成 |
| 多 agent 并行改同一模块 | 一个模块同一时间只允许一个会话写；其余只读 |

---

## 6. 为什么这条值得单列成规范

源包的真实事故：两个会话同时 `start_stop_play`，互相把对方的 Playtest 打断，导致**截图对不上、日志串台、结论互相矛盾**——最后花了更多时间争论"到底谁的证据是真的"。

这条与引擎无关：换成 Unity 的 Play Mode 或 UE 的 PIE，事故形态一模一样。

**识别信号**（出现任一即说明需要锁）：
- 同一份截图/日志出现两次不同结论
- 构建莫名其妙失败，重跑又好了
- 改动"没生效"，但代码确实改了
- 两个会话都说"我改好了"，diff 却对不上

## 7. 自动化入口（按引擎）

| 引擎 | 独占入口 | 备注 |
|---|---|---|
| Unity | Editor 单实例；`-runTests` / `-executeMethod` 批处理也算独占 | 批处理运行期间不要同时开 GUI Editor |
| UE | Editor 单实例；`UnrealEditor-Cmd.exe` / `-nullrhi` 运行也算独占 | 打包（`BuildCookRun`）与 Editor 同时跑会锁 DDC |

具体命令封装由项目自己提供；本文只定义**协议与纪律**，不绑定实现。
