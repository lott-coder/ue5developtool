# 代码清理（批量删除 / 重命名 / 迁移）

> 适用范围：删除死代码、批量重命名、目录迁移、格式化大范围改动。
> 这类操作的特点是**改动面大、收益不可见、出错极难回滚**——所以纪律比技巧重要。

---

## 1. 铁律

```
先度量，再动手；先小批，再铺开；每批都能单独回滚。
```

| 铁律 | 含义 |
|---|---|
| **先查引用** | 删任何东西前，先 `git grep` 全部引用点；编译器/链接器的报错是免费的检查器 |
| **先备份** | 动手前 `git tag clean-before-<topic>`，或至少确认工作区干净 |
| **小批推进** | 每批 ≤ 20 个文件，且能独立编译通过 |
| **可回滚** | 每批一个 commit，commit message 写清"删了什么、为什么" |
| **不混合** | 清理 commit 不夹带功能改动（否则无法 revert） |

**禁止**：
- ❌ 一次性全仓正则替换（跨文件边界必出事）
- ❌ 在脏工作区做大规模改动（分不清哪些是你的改动）
- ❌ 先删后查（先查后删）
- ❌ 清理顺手改逻辑（清理只做等价变换）

---

## 2. 五步法

### 步骤 1 · 盘点

| 要清理什么 | 怎么盘点 |
|---|---|
| 死代码 / 未使用类 | 编译器警告 + `git grep "ClassName"` 确认无引用 |
| 要重命名的标识符 | `git grep -w "OldName"` 列出全部引用点与文件数 |
| 要删除的资产 | 查引用（序列化引用/GUID/路径字符串）+ 引擎的"查找引用"功能 |
| 要迁移的目录 | 列出所有 include/依赖路径，改完靠编译器兜底 |

**产出**：一张"改动清单"（文件数、引用点数、风险点）。

### 步骤 2 · 备份与基线

```bash
git status                 # 必须干净
git tag clean-before-<topic>
# 记录基线：编译能过、测试能跑（否则清理后无法判断是不是你搞坏的）
```

### 步骤 3 · 小批执行

- 按**编译单元**分批（一个目录、一个模块、一类符号）
- 每批做完立刻编译；不通过就不进入下一批
- 用 IDE 的"重命名符号"而非全局替换（它理解语法树）
- 正则替换仅在**单文件内**使用，且替换后逐文件看 diff

### 步骤 4 · 验证

| 层次 | 动作 | 通过标准 |
|---|---|---|
| L0 | 编译 | 0 error，且**无新增 warning** |
| L1 | 测试 | 相关用例全绿 |
| 引用 | 引擎内检查 | 无 Missing / 无断引用 |
| 手工 | 抽几个调用点看 | 行为与清理前一致 |

**等价性判据**：清理前后行为必须完全一致。只要行为变了，就不是清理，是新功能——单独提交。

### 步骤 5 · 提交与记录

```bash
git commit -m "refactor(<scope>): 删除 <N> 个未使用类型（清单见下）"
```

commit body 记：
- 删除/重命名的清单（文件 + 原因）
- 基线证据（"清理前后 EditMode 42/42 绿"）
- 回滚命令（`git revert <sha>`）

## 3. 场景速查

### 删除死代码

1. 编译器警告 → 候选清单
2. 每个候选 `git grep -w` 确认零引用
3. 删 → 编译 → 测试 → commit
4. **不删**：反射/序列化按名引用的类型（删了运行时报错，编译不报）——先查配置/资产/存档里有没有名字

> 这条是本规范最容易踩的坑：**"编译能过"不等于"可以删"**。

### 批量重命名

| 对象 | 工具 | 注意 |
|---|---|---|
| 类型/方法 | IDE 重命名 | 能处理跨文件引用 |
| 序列化字段 | 手动 + Core Redirect / `FormerlySerializedAs` | 改名会丢数据 |
| 资产文件 | 引擎内重命名 | 外部移动会断引用 |
| 配置键/ID 字符串 | 双写过渡（新旧都能读）→ 迁移 → 删旧 | 直接改会让老数据读不到 |

### 目录迁移

- 先 `git mv` 保留历史
- 改所有 include/依赖声明（`Build.cs` / `asmdef` / 命名空间）
- 一次只迁一个目录

---

## 4. 反模式

| 反模式 | 后果 |
|---|---|
| "反正是死代码，一次删完" | 删到反射/序列化引用的东西，运行时炸 |
| 清理 commit 夹带修复 | 出问题时无法只回滚清理 |
| 全仓 `sed` 替换 | 替换到字符串常量、注释、文档 |
| 不编译就继续下一批 | 错误累积，定位成本指数上升 |
| 删完不跑测试 | 编译能过但行为已变 |
| 清理没有独立分支 | 与功能改动纠缠，回滚困难 |

---

## 5. 完成判据

- [ ] 基线（清理前）编译与测试状态已记录
- [ ] 改动清单完整（文件、引用点、风险）
- [ ] 每批独立 commit 且能单独编译
- [ ] 清理后编译 0 error、无新增 warning
- [ ] 相关测试全绿（或明确说明哪些无法自动验证）
- [ ] 无反射/序列化按名引用被误删
- [ ] 抽检调用点行为一致
- [ ] 回滚命令已写进 commit body
