# 编码约定（UE5 / C++）

> 适用范围：`Source/**/*.h`、`*.cpp`。与 [架构.md](架构.md) 的模块边界冲突时，以架构为准。
> 总原则：**跟随 Epic 的命名与反射约定**，不要引入 C#/Unity 风格。

---

## 1. 命名

| 元素 | 规则 | 示例 |
|---|---|---|
| `UObject` 派生类 | `U` + PascalCase | `UEconomySubsystem` |
| `AActor` 派生类 | `A` + PascalCase | `AShopKeeper` |
| 结构体 | `F` + PascalCase | `FPriceRule` |
| 枚举 | `E` + PascalCase | `EPurchaseResult` |
| 接口 | `I` + PascalCase | `ISaveable` |
| 模板 | `T` + PascalCase | `TObjectPtr` |
| 类型 / 函数 / 属性 | PascalCase | `TryBuy`、`TotalCoins` |
| 局部变量 / 参数 | PascalCase（Epic 风格） | `ItemId`、`DeltaTime` |
| 布尔 | `b` 前缀 | `bIsReady`、`bGranted` |
| 常量 | `static constexpr` + PascalCase | `MaxStackSize` |
| 日志分类 | `DECLARE_LOG_CATEGORY_EXTERN` + PascalCase | `LogEconomy` |
| 文件名 | = 主类型名（去掉前缀也可） | `EconomySubsystem.h` |

> **不要**用 `m_` / `_` 前缀（Unity/C# 习惯）。UE 用 `b` 前缀区分布尔，其余靠 PascalCase + 语义。

## 2. 反射宏（漏一个就有后果）

| 宏 | 漏了的后果 |
|---|---|
| `UCLASS()` | 无法被 `NewObject`、无法被 BP 继承、GC 不认 |
| `UPROPERTY()` | **不被 GC 追踪**（指针悬空）、不序列化、不可复制、BP 不可见 |
| `UFUNCTION()` | 不可被 BP 调用/重载、不可做 RPC |
| `GENERATED_BODY()` | 编译失败（这是好事） |

```cpp
UCLASS()
class GAMEFRAMEWORK_API UEconomySubsystem : public UGameInstanceSubsystem
{
    GENERATED_BODY()

public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override;

    UFUNCTION(BlueprintCallable, Category = "Economy")
    bool TryBuy(const FString& ItemId);           // BP 可调用 → 必须校验输入

    UPROPERTY(BlueprintReadOnly, Replicated, Category = "Economy")
    int64 TotalCoins = 0;                          // 复制 + 只读

private:
    UPROPERTY()                                    // 必须！否则 GC 不追踪
    TObjectPtr<UEconomyConfig> Config;
};
```

**硬规则**：
- 所有 `UObject*` 成员必须 `UPROPERTY()`，且用 `TObjectPtr<T>`（UE5）
- 对外暴露给 BP 的函数必须**自己校验输入**（BP 传什么都有可能）
- `BlueprintReadWrite` 慎用——能只读就只读

## 3. 对象创建与生命周期

| 规则 | 说明 |
|---|---|
| `UObject` 用 `NewObject<T>()` | **禁止** `new` / `delete`（GC 管理） |
| 组件用 `CreateDefaultSubobject<T>()` | 仅在构造函数内 |
| `AActor` 用 `SpawnActor<T>()` | 不要 `new` |
| 释放 | 交给 GC：清空 `UPROPERTY` 指针 + `MarkAsGarbage()`（必要时）；**禁止** `delete` |
| 构造函数中 | 不访问 `GetWorld()`、不查其他 Actor、不做游戏逻辑 |
| `BeginPlay` | 可访问 World，但仍不得假设其他 Actor 已就绪（用 `OnActorReady` 或延迟一帧） |
| `EndPlay` | 解绑委托、清理计时器 |

---

## 4. Tick 纪律

`Tick` 是性能问题的第一来源。**默认不 Tick**：构造函数里 `PrimaryActorTick.bCanEverTick = false;`，确有需要再开。

| 禁止（`Tick`/`TickComponent` 内） | 替代 |
|---|---|
| `FindComponentByClass` / `GetComponentByClass` | 缓存到 `UPROPERTY` 成员（`BeginPlay` 中） |
| `GetAllActorsOfClass` | 事件驱动 / 维护注册表 |
| `FString` 拼接、`TArray` 扩容 | 预分配 `Reserve`、用 `FName` |
| `LoadObject` / 同步加载 | 提前加载（软引用 + `StreamableManager`） |
| `Cast<T>` 链 | 缓存结果或改用接口 |
| 每帧 `UE_LOG` | 用 `UE_LOG(LogTemp, Verbose, ...)` 或加频率限制 |

**用计时器/委托替代 Tick**：`GetWorldTimerManager().SetTimer(...)`、`OnComponentBeginOverlap`、复制回调。

---

## 5. 字符串与容器

| 用途 | 类型 |
|---|---|
| 标识符（ID、标签、资产名） | `FName`（比较快、自动去重） |
| 显示文本（可本地化） | `FText` |
| 临时/调试/路径 | `FString` |

- 禁止用 `FString` 做 map key 或高频比较——用 `FName`
- `TArray` 已知大小先 `Reserve`
- 大对象用 `TSharedPtr` / `TUniquePtr`；`UObject` **不**用智能指针
- 遍历时删除：用 `RemoveAtSwap` 或在遍历后统一处理

## 6. 校验与失败处理

| 场景 | 做法 |
|---|---|
| 编程错误（不该发生） | `check()` / `checkf()`（Shipping 下被编译掉） |
| 可恢复的异常状况 | `ensure()` / `ensureMsgf()`（记录一次，不中断） |
| 业务失败（余额不足等） | 返回 `bool` + `OutReason`，或 `TOptional<T>` |
| 存档/网络 IO 失败 | 显式失败 + 日志 + 阻断流程（**禁止静默降级**） |

```cpp
// 业务失败用返回值，不用异常（UE 不鼓励异常）
bool UEconomySubsystem::TryBuy(const FString& ItemId, FString& OutReason)
{
    if (!IsValidItemId(ItemId)) { OutReason = TEXT("INVALID_ITEM"); return false; }
    // ...
    return true;
}
```

**禁止**：`try/catch`（UE 默认关闭异常）、空 `catch`、失败后继续执行不改状态。

## 7. 网络与复制

| 规则 | 说明 |
|---|---|
| Server RPC 必须 `WithValidation` | 否则不校验调用者输入 |
| Server RPC 实现体首行 `if (!HasAuthority()) return;` | 双保险（引擎已保证，但便于审查） |
| RPC 命名前缀 | `Server` / `Client` / `Multicast`——**前缀错会静默不复制** |
| 复制属性 | `UPROPERTY(Replicated)` + `GetLifetimeReplicatedProps` 两处都要有 |
| `ReplicatedUsing` | 需要客户端响应时用回调，不要在 `Tick` 里轮询 |
| 不要复制的东西 | 高频变化的临时表现数据（用 RPC 或用本地预测） |

---

## 8. 头文件与编译

- **IWYU**：头文件里用前置声明，`#include` 放 `.cpp`
- `*.generated.h` 必须是**最后一个** include
- 模块 API 宏：`GAMECORE_API` 等，导出类/函数必须有
- 避免在头文件里 include 重量级头（会拖慢全量编译）
- 循环依赖用前置声明 + 接口

---

## 9. 注释与可读性

- **注释中文，标识符英文**（沿用源包团队约定）
- 解释**为什么**，不解释**是什么**
- 公开 API 用 UE 文档注释风格：
  ```cpp
  /** 尝试扣除金币；余额不足时不产生任何变更。 */
  bool TrySpend(int64 Amount);
  ```
- 魔法数必须注明来源（策划表 / 公式 / `R{n}`）
- 禁止被注释掉的死代码进主干

---

## 10. 禁止清单（一票阻断）

- ❌ `UObject*` 成员缺 `UPROPERTY()`（GC 悬空）
- ❌ `new` / `delete` 管理 `UObject`
- ❌ 构造函数里访问 `GetWorld()` 或做游戏逻辑
- ❌ `Tick` 内 `FindComponentByClass` / `GetAllActorsOfClass` / 同步 `LoadObject` / `FString` 拼接
- ❌ `HasAuthority()` 缺失的 Server RPC 业务逻辑
- ❌ 写死 `"/Game/..."` 路径字符串
- ❌ `try/catch` 或空 `catch`
- ❌ 存档失败静默用默认值继续
- ❌ 公开 `BlueprintReadWrite` 的可变权威状态（BP 可写 → 权威失效）
- ❌ 业务规则写进 Blueprint（见 `架构.md` §7）
