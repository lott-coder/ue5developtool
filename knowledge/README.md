# `knowledge/` 项目知识库

> 回答"**怎么做 / 为什么这么做 / 踩过什么坑**"（how）。
> 纯文件，无向量库；检索靠 Grep + 目录约定。

---

## 与 spec 的边界

| 写这里 ✅ | 不写这里 ❌ |
|---|---|
| 设计取舍的理由 | "系统必须做 X"（→ `spec/`） |
| 踩过的坑（现象/根因/正解） | 改了哪些文件（→ `change/03-plan.md`） |
| 不可见约束（线程/顺序/时序） | 代码里一眼可见的实现复述 |
| 已知技术债 | 临时调试状态 |

**判断标准**：一年后的人（或 AI）读到这条，能少踩一次坑吗？不能就别写。

---

## 文件组织

- **一个模块一文件**：`knowledge/{module}.md`
- 模块名必须与 `change/` 目录一致
- 新模块先更新 `README.md` 索引
- **禁止**按技术层分（不要 `network.md` / `ui.md` 这类跨模块文件）
