# `spec/` 活规格层

> **本目录是当前真相源**：回答"系统现在**必须**是什么行为"（what）。
> **只读**。唯一更新入口是 `/workflow archive` 的 delta 合并。**禁止手改。**

---

## 三层职责（不要混）

| 层 | 回答什么 | 谁维护 | 可否手改 |
|---|---|---|---|
| `spec/{module}.md` | 现在必须是什么行为（契约） | `/workflow archive` | ❌ 禁止 |
| `knowledge/{module}.md` | 怎么做、为什么、踩过什么坑 | `/knowledge-set` | ✅ 可 |
| `change/{module}/**` | 这次改了什么、为什么 | `/workflow plan` | ✅ 可 |

**为什么 spec 禁止手改**：绕过 delta 直接编辑 = 真相源被旁路污染。之后所有迭代都会基于"文档说有、代码没有"的假前提设计，而这种错误**在编译期和测试期都不会暴露**。

---

## 文件格式

每个模块一份：`spec/{module}.md`

```markdown
# {module} 模块规格（活规格基线）

> 由 change/{module}/{subCategory}/v{X.Y.Z} 的 07-spec-delta.md 归档合并生成（YYYY-MM-DD）。
> 本文件是当前真相源（what）；只读——更新唯一入口是 /workflow archive 的 delta 合并。

## R1 — <能力标题>
系统必须 <一句话行为契约>。
### 场景: <场景名>
- 当 <前置条件/输入>
- 则 <权威端结果>
```

**约定**：
- `R{n}` 全局唯一，**只增不复用**（删除的编号永久保留空洞，不复用给新需求）
- 每条能力至少一个场景，场景用「当…则…」
- 「则」必须落在权威端（见 `开发规范/架构.md` §2）
- 能力标题下不写实现细节（那是 knowledge 的事）

---

## 生成时机

- **首次**：某模块第一次 `archive` 时自动生成基线
- **后续**：每次 `archive` 按 delta 增量合并（ADDED 追加 / MODIFIED 整段替换 / REMOVED 删除）
- **本包不 ship 实体 spec 文件**：没有历史迭代的模块不应凭空造基线
